# Hoolam: system documentation

Oct 11, 2026 · @Noah

## What Hoolam is

Hoolam is a WhatsApp escrow service for buying and selling in Nigeria: the buyer pays Hoolam, Hoolam holds the money, and the seller is paid when the buyer is happy. Everything happens in one WhatsApp chat, with WhatsApp forms for the longer steps.

- **Company:** HOOLAM DIGITAL PLATFORM LTD (RC 9919417), 8 Delta Bakery Road, Woji, Rivers State.
- **Who uses it:** buyers and sellers on WhatsApp and Instagram; Hoolam's team uses the staff console.
- **Hoolam's WhatsApp number:** set in Console → Settings → WhatsApp (currently 08117663890).
- **Code:** github.com/Levinders/hoolam (private). Server: console.hoolam.com. Website: hoolam.com.

**Keeping this doc current:** this doc is updated as the last step of every change. The same content is kept in the repo as `docs/SYSTEM.md`, so the code and its documentation travel together. The change log at the end says what changed and when.

## Stack and platforms

One Node.js server does everything (WhatsApp bot, forms endpoint, payments, console, private pages); the website is a separate static site. Both deploy from the GitHub repo on every push to `main`.

| Images | sharp (resize, WebP/JPEG) | inside the server |

**Plans:** both Render services are on the free plan. The server sleeps after 15 minutes without traffic and takes about a minute to wake; move it to Starter once real money moves.

**Open items:** the Monnify sandbox error, SCUML approval, switching Monnify settlement to the corporate account, the go./pay. domains, and possibly moving Supabase.

## Architecture

Every WhatsApp message and payment notice is first saved to the database, then handled, so nothing is lost if the server restarts mid-way. Money moves only after the payment provider confirms it, and every naira is recorded in a double-entry ledger.

_Diagram (in the Claude doc): system architecture, one server with five parts inside, connected to Meta, the team, Supabase, Monnify and the website._

Everything passes through the one server: messages come in from Meta, money moves through Monnify, and the deal service (highlighted) is the only part that changes orders or money.

### How a message moves

1. Meta posts the message to `/webhook/whatsapp`; the server checks Meta's signature, saves it to `webhook_events` and answers at once.
2. The conversation engine (`src/whatsapp/flow.ts`) reads the person's chat state (`chat_sessions`) and decides the reply.
3. Order changes go through the deal service (`src/deals/service.ts`) inside one database transaction, with the ledger lines.
4. Replies go out through the messenger (`src/whatsapp/client.ts`): a chat message inside 24 hours, otherwise the approved template, otherwise it waits in Needs action.
5. Live forms (My orders, a single order, the buyer's review) call `/flows/endpoint`, encrypted with the server's key.

### Server addresses

| Address | What it serves |
| --- | --- |
| `/webhook/whatsapp` | Messages and status updates from Meta |
| `/flows/endpoint` | The encrypted endpoint for live WhatsApp forms |
| `/webhook/payments` | Payment and payout notices from Monnify |
| `/console` | The staff console and its API (`/console/api/...`) |
| `/o/:code?k=` | Private order page (buyer's link, seller's link, or the neutral link) |
| `/s/:slug` | A seller's public trust page |
| `/:code`, `/v/:code`, `/chat` | Short links that open the WhatsApp chat at the right step |
| `/site.json` | Live fees, limits, timings and contact details for the website |
| `/health` | Health check for Render |

### Database (Postgres, migrations in `db/migrations`, run on every start)

| Area | Tables |
| --- | --- |
| People | `users`, `bank_accounts`, `user_photos`, `alert_refusals` (who said Not me to whom) |
| Orders | `deals`, `deal_events`, `deal_photos`, `deal_notes`, `deal_ratings`, `disputes` |
| Money | `payment_intents`, `payouts`, `ledger_entries` |
| WhatsApp | `chat_sessions` (state + last message time), `webhook_events`, `outbound_messages`, `media` |
| Team | `staff`, `staff_invites`, `staff_sessions`, `audit_log`, `support_requests`, `inbox_dismissals` |
| System | `settings` (console values), `app_secrets` (forms key), `contact_optouts` (old, now empty) |

### Ledger accounts

| Account | Meaning |
| --- | --- |
| `cash:<provider>` | Money at Monnify |
| `held:deal` | A buyer's money held for an order |
| `payable:seller`, `payable:buyer`, `payable:courier` | Owed to a seller, back to a buyer, or to a rider/driver, until the transfer lands |
| `revenue:fees` | Hoolam's fee plus the transaction fee |

### Background jobs

- **Every 30 seconds:** retry webhooks that failed, check payouts still in progress.
- **Every 10 minutes:** refresh template approvals from Meta, then the sweep: close orders the seller didn't accept, close unpaid orders, pay sellers automatically after the handover window, remind sellers to dispatch, give buyers their overdue options, ask buyers if items arrived.
- **On every start:** run migrations, sync the menu commands and ice breakers, make sure every template and form exists on Meta, and register the forms key.

## Fees and money

Whoever starts the order pays Hoolam's fee; the other side pays a flat transaction fee. Each person only ever sees their own fee: in the chat, the forms and their own order page link.

|  | Buyer starts the order | Seller starts the order |
| --- | --- | --- |
| Hoolam fee (2.5%, ₦300 to ₦5,000, rounded to ₦100) | Buyer pays it on top | Taken from the seller's payout |
| Transaction fee (by band) | Taken from the seller's payout | Buyer pays it on top |
| Example: ₦10,000 order | Buyer pays ₦10,300, seller gets ₦9,500 | Buyer pays ₦10,500, seller gets ₦9,700 |

- **Fee lines people see:** the buyer sees "Hoolam fee" or "Transaction fee" (whichever is theirs) and "You pay"; the seller sees theirs and "You receive". Staff see both in the console.
- **What's stored on each order:** `price_minor`, `fee_minor` (Hoolam fee), `txn_fee_minor` and `txn_fee_payer`, `buyer_pays_minor`, `seller_gets_minor`, `fee_payer`. An order keeps the fees it started with, even if the console changes later.
- **The band** is chosen on the total price, delivery included. Tiny orders never leave the seller with nothing.
- **All money is in kobo** inside the system (₦1 = 100).

### How money moves

1. **Paying:** Monnify gives the buyer a one-time account number (valid about 40 minutes). When the transfer lands, the server asks Monnify to confirm the real amount before anything changes. Cash moves to `held:deal`.
2. **Short payment:** the order isn't marked paid; the amount is owed back to the buyer and the team is alerted. **Overpayment:** the order is paid and the extra is owed back.
3. **Rider or driver:** when the right handover code is entered, their delivery fee is paid at once from the held money.
4. **Release:** the seller gets what's still held, minus Hoolam's fee and any transaction fee. Both fees go to `revenue:fees`.
5. **Refund:** the buyer gets back everything still held, including Hoolam's fee and any transaction fee they paid. A delivery fee already paid to a rider can't come back. The seller pays no transaction fee on a refunded order.
6. **Payout checks:** transfers waiting for an OTP or stuck are retried or shown in the console's Money page.

## Menus and chat routes

Everyone starts on the buying menu; becoming a seller (a one-time setup that creates the trust card) unlocks the selling menu, and "Switch to…" moves between them. The menu shown follows the person's last order.

| Buying menu | Selling menu |
| --- | --- |
| 🛒 Buy something: your money's held until you're happy | 🏷️ Sell something: send your buyer a safe-pay link |
| 🔑 I have an order code | 📋 My orders: track your sales and payouts |
| 📋 My orders: all transactions, track your orders | 🛡️ My trust card: your public brand image |
| 🔍 Check a seller | 🏦 Payout account |

**Help (both menus):** 🚩 Report a problem · 💡 How it works · 🙋 Talk to a rep ("Live rep within" the console's reply time) · 🔁 Switch to selling / buying.

**Other ways in:**

- **First message:** a welcome with "I'm buying", "I'm selling", "How it works".
- **Greetings** (hi, hello, menu, good morning…) open the menu.
- **Slash commands** (shown by WhatsApp when typing /): /menu, /buy, /sell, /pay, /orders, /check, /card, /account, /problem, /switch, /fees, /help.
- **Ice breakers** (shown before the first message): "I want to buy something safely", "A seller sent me an order code", "I want to sell something safely", "How does Hoolam protect my money?"
- **Order codes** typed anywhere (HL-7K2QF, or without the dash) open that order.

**Rules every chat message follows:**

- **Main menu** is the last option on every message with room for it: plain messages get the button, 1 or 2 buttons get it last, lists get it as the last row. Messages with 3 buttons, the menu itself, and the trust-card text meant for forwarding are left as they are. Tapping it always resets the current step.
- **Phone numbers** are shown and typed the Nigerian way (08117663890). +234 is added behind the scenes. Hoolam's own number is the example in every hint, and typing it as someone else's number is refused.
- **Bold** marks names, amounts, order codes, addresses, dates and warnings.
- **Bank accounts:** send just the 10-digit number and pick the bank from a list (see Dispatch), or type "0123456789 GTBank". The account name is looked up and shown with the full number to confirm.
- **Voice notes** aren't understood yet; the bot asks for text.

## Buy something, end to end

A buyer describes what they agreed, Hoolam alerts the seller, the seller accepts or updates the price, the buyer pays Hoolam, and the order moves to dispatch. Each step below is done in a WhatsApp form when it can open, with the chat as the fallback. "📨" marks a message that goes as an approved template when the person hasn't messaged Hoolam in 24 hours.

_Diagram (in the Claude doc): a buyer's order in 8 steps: buyer orders → checks and sends → seller decides → buyer pays Hoolam → seller dispatches → code at handover → buyer is happy (or the window passes) → seller is paid. After payment, a problem freezes the money until a rep releases or refunds it._

The top row runs until the money is held; the bottom row runs right to left from dispatch to the seller's payout.

### 1. Starting

- **Ways in:** Buying → Buy something, "I'm buying" on the welcome, /buy, or **Buy from them** on a seller's trust card (skips the seller's-number question).
- **Form message** "🛒 Buy safely" with **Start my order**. Footer: "Prefer typing? Just send the item name."
- **The buyer form, 3 screens, every field required:**
  1. What are you buying? Item name, description, category (dropdown), total price including delivery (15000 or 15k). **Continue**.
  2. Where and when? Delivery address, "When are you expecting it?" (date), seller's WhatsApp. **Continue**.
  3. Photos: 1 to 3 from gallery or camera (max 25 MB), "Nothing to pay yet." **Review my order**.
- **Chat fallback**, one question at a time: item, description, category (list), price, address, **expected date** (Tomorrow / In 3 days / In a week, or a typed date like 25 Oct or 25/10), photos (up to 3, or No photos / Done), seller's WhatsApp (or Skip for a link).
- **Anything missing or wrong** is asked again in the chat: a price above the largest order, a number it can't read ("Try it like 08117663890"), Hoolam's own number ("That's Hoolam's number. Please type the seller's WhatsApp number.").

### 2. Checking the order

- **Form message** "🛒 Check your order" (item and total in bold) with **Review order**.
- **Order summary screen:** photos, item (bold), description and category; in bold the total price, deliver to, expected by and the seller's full WhatsApp number; plain "Delivery is included in the total, if any" and the Hoolam fee rule from the console ("2.5% of the total, starting from ₦300, at most ₦5,000"); **Nothing to pay yet. You pay after the seller accepts.** then "Is everything right?"
- **Send to seller** creates the order (a second tap does nothing). **Edit order** sends the buyer form to the chat with every answer filled in (photos kept unless new ones are added). **Start again** sends a blank form.
- **Chat fallback:** the same summary with Send to seller · Edit order · Start again. Edit order lists item, description, category, price, address, expected date, photos, seller's WhatsApp; it asks only the one picked, then shows the summary again.

### 3. Order created

- **Buyer:** "✅ Order HL-XXXXX is ready", "we've alerted the seller" with a backup link to forward, the console's accept time ("They have 48 hours to accept"), the buyer's private order page, **Cancel order** · Main menu.
- **No alert when:** there was no number (they get the link to send), it's their own number, or that number said "Not me" to this same buyer before ("That number said it isn't your seller last time… If it is, send them this link yourself"). If WhatsApp can't reach the number, the buyer is told to send the link.
- **Seller (📨 template when needed):** "**New order request** on **Hoolam**" with buyer, item and total price on bold lines; **View order** · **Not me**.
- **Not me** closes this order only. That buyer can't alert that number again; everyone else still can. The console shows it on both people's pages.

### 4. The seller looks at it

- **View order** opens the single-order form: "🛒 Ada wants to buy from you", photos, item (HL-X), description, category; in bold the total price, "Transaction fee −₦500", "You receive", deliver to, expected by; the accept-by hint.
- **Chat fallback:** the photos, then the card (buyer, item, total in bold; buyer's record; description; address and date; total / transaction fee / You receive, minus a rider's fee if they send one; how it works; accept within N hours).
- **Accept** · **Update price** · **Decline**:
  - **Accept:** with a payout account it's done ("✅ Order accepted… **Don't send anything before then.**"); without one they send the account number in the chat, pick the bank, confirm the name, then it's accepted.
  - **Update price:** "Your price (₦)" and "Why the new price?" (required, up to 150 characters). Chat asks the price, then the reason.
  - **Decline:** closes it. In the chat, a seller alerted by number picks **Not interested** or **Wrong number** (the same as Not me).
- **No answer in time** (console: Seller has to accept within, 48 h): the order closes, the buyer is told, 📨 if needed.

### 5. The buyer answers a price update

- "✏️ **Bayo** updated the price": the item, old price crossed out → **new price**, "💬 Reason: …", New price / Hoolam fee / **You'd pay**. **Accept new price** · **Cancel order**. 📨 if needed.
- **Accept:** the order goes on at the new price. The seller gets "🎉 **Ada** accepted your price for order **HL-X**. You'll receive **₦X**… **Don't ship before we confirm the money is held.**"

### 6. Paying

- **Buyer (📨 if needed):** "🎉 **Bayo** **accepted your order!**", the seller's trust line, the item, Total price / Hoolam fee / **You pay**, "**Your money stays with Hoolam until you have your item and you're happy.** (Order **HL-X**)". **Pay now** · **Seller's record** · **Cancel order**.
- **Pay now:** "Transfer exactly ₦X to:" a one-time account number, bank and name, valid for the minutes shown; **New account number** if it expires.
- **Payment lands:** buyer gets "✅ Received **₦X**. **Your money is held safely by Hoolam.** We've told Bayo to send your item…"; seller gets "💰 **Ada** has paid for order **HL-X**. Your **₦X** is held safely by Hoolam. Dispatch it now…" with **Dispatch now** · **Can't fulfil** (📨 if needed).
- **Not paid** within the console's window (72 h): the order closes.

Dispatch, handover, payment to the seller, problems and refunds continue below.

## Selling, the trust card and becoming a seller

Sellers can also start an order and send the buyer a safe-pay link; this route works today but its redesign (like the buy route) is still to be specified.

### Becoming a seller (once)

- Triggered by Sell something, My trust card, or Switch to selling the first time.
- Two questions: the name buyers should see (or **Use this name** from WhatsApp), and the city (or **Skip**). This creates the **trust card** and unlocks the selling menu.

### Sell something (seller starts the order)

1. **Seller form** "🏷️ Sell safely": item, price, buyer's WhatsApp (optional), then up to 3 photos (optional). Chat fallback asks the same, one at a time.
2. **Payout account** if they have none: account number, pick the bank, confirm the name (full number shown).
3. **Check your order:** item, photos, buyer's WhatsApp, Price / Hoolam fee / **You receive**, "You started the order, so you pay Hoolam's fee." **Create order** · **Start again**.
4. **Order ready:** the link to send the buyer. If a number was given, the buyer gets 📨 "Payment request on Hoolam" with **View order** · **Not me** (Not me works per person, as for sellers).
5. **The buyer opens it:** photos, then "🛒 Order **HL-X** from **Bayo**", the seller's trust line, Price / Transaction fee / **You pay**, "**Your money stays with Hoolam, not the seller.**" **Pay now** · **Seller's record** · **Cancel order**. The seller is told the buyer opened it.
6. **Paid:** the seller gets "💰 Good news: **Ada** has paid for order **HL-X**. Your **₦X** is held safely by Hoolam. Ship the item now…" with **I've sent it**.
7. **Shipped:** the seller can add proof (a photo or a tracking number); the buyer gets "Your item is on the way" with **I'm happy** · **Problem**. Release and problems work as for buyer orders.

### My trust card and public page

- **My trust card:** the record buyers see, counted only from real paid orders: orders completed, different buyers, how fast they ship, problems and how they ended, ratings (shown as a % from 5 ratings), bank verified and whether the name matches, links.
- **Buttons:** Share my link (a ready-to-forward message), Edit my page (photo, name and city, Instagram, TikTok, Facebook, website), Hide my page.
- **Public page** `/s/<slug>`: the card with a photo, a share image, and **Buy safely**, which starts a protected order with that seller.
- **Check a seller** (buyers): send a number or an order code to see that seller's record, then **Buy from them**.
- **Ratings:** after release the buyer is asked "To help other buyers like you, how was Bayo?" 👍 Great / 👎 Not great (a short private note for the team after 👎).

## Dispatch, handover, release and problems

Once the buyer has paid, the seller says how the item travels, the buyer gets a 4-digit handover code, and the right code pays the rider at once; the seller is paid when the buyer is happy or automatically after the console's window.

### 7. Dispatch

- **Dispatch now** opens the order, then the dispatch screen: "Ada · HL-X · item", then 📍 Pickup / 🛵 Dispatch rider / 🚌 Waybill.
- **Pickup:** the pickup address is required. Seller sees "✅ Ready for pickup… **Ask for the code before you hand over the item.**"
- **Rider or waybill** ("🛵 Ada · HL-X"), every field required:
  1. Rider's name (rider only), Rider's / Driver's number, delivery fee (less than what the seller receives), delivering to (prefilled with the buyer's address), account number. **Continue**.
  2. **Bank** from a list: OPay, Moniepoint, PalmPay, Kuda, GTBank, Fidelity and Zenith always first, then only the banks that account number can belong to (the Nigerian account-number check), then "My bank isn't listed" with a box to type it. **Check account**.
  3. The name is looked up and shown in bold with the full number: "This account belongs to MUSA IBRAHIM (OPay 8031234567). The rider's fee of ₦2,000 goes here once the handover code is right." Tick **Yes, this is the right account**. **Dispatch**.
- **Chat fallback:** the same questions one at a time; for the account, send just the number and pick the bank from a list (or "Other bank" and type it), then confirm.
- **Seller after dispatching:** "✅ **Ada** · **HL-X** is dispatched with Musa", the rider's fee, "**Tell your rider: ask the receiver for their 4-digit handover code…**", the order page. **Enter code** · Main menu.
- **Can't fulfil:** "The buyer gets all their money back… This can't be undone." **Yes, refund buyer** · **Keep the order**.
- **Not dispatched** after the console's time (12 h): "⏰ **Ada** · **HL-X** (item) is paid and waiting to be dispatched" with Dispatch now · Can't fulfil. 📨 if needed.

### 8. The buyer is told

- **Chat:** pickup address, or the rider's name, number and drop-off, or the driver's number and location; "🔑 Your handover code: **1234**. Give it only to the rider when the item is in your hands"; the order page. **Show my code** · **Problem**.
- **📨 Template** (no code in it, Meta rejects codes): "Good news: your order HL-X has been dispatched…" with **Delivery details** · **Problem**. Delivery details sends the full chat message above, code included.
- **Expected date passed, not dispatched:** "⏰ …hasn't been dispatched yet…" with **Send reminder** · **Refund me** · **Wait a bit**. 📨 if needed.

### 9. Handover

- The seller taps **Enter code** (a form screen, or the chat) and types the receiver's 4 digits.
- **Right code:** the rider or driver is paid their fee at once. Seller: "✅ Code correct… You'll be paid when the buyer taps I'm happy, or automatically after 24 hours" (the console's time). Buyer: "📦 Order HL-X has been handed over to you. Open it and check it now…" with **I'm happy** · **Problem** (📨 if needed).
- **Wrong code:** "❌ That code doesn't match… N tries left." After the console's number of tries (5), the order locks and a rep finishes the handover.

### 10. Finishing

- **I'm happy**, or the console's window passes with no problem: the seller is paid what's still held, minus their transaction fee and the rider's fee. Buyer: "✅ Done. We're paying Bayo now… To help other buyers like you, how was Bayo?" Seller: "You've been paid. ₦X has been sent to your bank account" (📨 if needed).
- **No code ever entered:** the buyer is asked "Has your item arrived?" after the console's reminder time (24 h); after the flag time (72 h) the order appears in the console's Needs action.

### 11. Problems and refunds

- **Problem** (from a message, My orders, or Report a problem): the money is frozen at once and the seller is told (📨 if needed). The buyer is asked what's wrong (text or a photo), then for a refund account if there isn't one. "Case C-XXXXXX is open… A real person will reply within" the console's problem reply time. A rep decides in the console: release or refund.
- **Refunds** (seller can't fulfil, buyer taps Refund me, or a rep decides): the buyer gets back everything still held, fees included; a rider's fee already paid can't come back; no transaction fee for the seller. The buyer is told when it lands (📨 if needed).
- **Talk to a rep:** the message goes to the console's Support inbox; "A live rep replies right here within" the console's reply time.

### 12. My orders and the private order page

- **My orders** (form): Pending / Completed / All with counts, then 20 per page; each row reads "**Bayo · HL-X · ₦X**" (the other person's name, the code, the amount) with the item and next step; opening one shows the Order summary with only its next action.
- **Private order page** (`/o/HL-X?k=…`): photos, a status timeline, delivery details and that person's own money lines (the buyer's link and the seller's link differ). It never shows the handover code.

## WhatsApp forms (Flows)

The server creates every form on Meta when it starts; a changed form gets a new name (a hash of its contents), because published forms can't be edited. If a form can't be sent, the chat asks the same questions instead.

| Form (name on Meta) | Kind | What it does |
| --- | --- | --- |
| Buyer form (`hoolam_buy_…`) | Static | Item, delivery, photos; answers arrive in the webhook |
| Buyer edit form (`hoolam_buyedit_…`) | Static, filled in | The buyer form with their answers; photos optional (kept unless replaced) |
| Seller form (`hoolam_sell_…`) | Static | Item, price, buyer's number, photos |
| My orders (`hoolam_orders_…`) | Live | Filter → list → order → dispatch / rider details / code → done |
| Single order (`hoolam_order_…`) | Live | Opens on one order: a new order for a seller, the buyer's review, dispatch, enter code |

### Live forms

- **Endpoint:** `/flows/endpoint`. Requests are encrypted (RSA-OAEP-SHA256 for the key, AES-128-GCM for the data). The key pair is made by the server and kept in `app_secrets` (or `FLOWS_PRIVATE_KEY`), and the public half is registered with Meta on every start.
- **Who's asking:** each form carries a signed token (`o1.<phone>.<mode>.<entry>.<code>.<expiry>.<signature>`), so nobody can open someone else's orders; tokens last 72 hours (24 for the buyer's review).
- **Meta's rules the forms follow:** routes only go forward; a form opens only on its first screen; at most 10 connections between screens per form; at most 2 links and 3 images per screen; a button label up to 35 characters, a link up to 25, a list row title up to 30.
- **What the order screen shows:** heading, up to 3 photos, the item in bold, description and category, the money, address, dates and codes in bold, other details plain, a hint, a bold warning when needed, then the one main button and up to two links.

### Backup versions

If Meta refuses the fields that switch between required and optional, the server uses a backup version and logs "using the backup version". In it every field is plainly required, each on its own screen:

- **Single order:** order → dispatch method → pickup address, rider details or driver details → bank → confirm the account → done (10 connections). The handover code is typed in the chat.
- **My orders:** filter → list → order → code → done; Dispatch now sends the single-order form to the chat.

## The staff console

The console at console.hoolam.com is where the team watches orders, moves money when needed, answers people and changes settings. Every action is saved to the audit trail with who did it and why.

**Sign-in:** email, password and an authenticator code (2-step). The first owner is set up with `ADMIN_TOKEN`; others are invited by email link.

| Page | What it's for |
| --- | --- |
| Home | Needs action (stuck orders, waiting messages, open problems, support), today's numbers, fees earned |
| Orders | Every order with filters; an order shows its timeline, photos, people, money (both fees), dispatch details, notes and messages |
| Problems | Open disputes with the buyer's evidence; release or refund |
| Money | Ledger balances (held, owed, fees earned), payouts, retries, OTP approvals, export |
| Buyers & sellers | Each person's record, orders, bank accounts, trust card, who they said "Not me" to, order limit, pause, **Message them** |
| Support | The inbox of "Talk to a rep" and problem messages, with replies |
| Insights | Trends: orders, value, fees, conversion |
| Settings | Fees, Limits, Timing, Payments, WhatsApp (number, switches, template statuses), Contact, Brand, Website images, History |
| Team, Audit | Staff and roles; the full audit trail |

**Roles:** Owner (everything, including fees, limits and Hoolam's number), Admin (orders, money moves, people, most settings), Finance (payouts, exports, audit), Support (messages, notes, support inbox).

### Messages from Hoolam support

- From a person's page (**Message them**), an order (**Message** → to the buyer or the seller), or a support thread (**Send**).
- The box takes up to 600 characters with a live count, as one paragraph (line breaks become spaces).
- It goes as "🙋 **Hoolam support:** an update about your order **HL-X**. … Reply here if you have any questions.", using the order you're on or the person's latest order. This works at any time, even outside 24 hours, once Meta approves `hoolam_support_update`.
- Someone with no orders gets a chat message instead (only possible within 24 hours of their last message); the console says so if it can't send.
- Their next message goes straight to the Support inbox, tagged with the order.

### Settings worth knowing

- **Fees:** Hoolam's fee and the two transaction fee tables (each folds open with an arrow), with a "Try it" calculator.
- **Changes apply to new orders.** Fee, limit and number changes also rebuild the website within about a minute.
- **Phone numbers** are typed as 08117663890; the country code is added behind the scenes.

## Operations

A push to `main` on GitHub deploys both Render services; database changes run automatically when the server starts.

| Line | Meaning |

- `npm run dev` (local server), `npm test` (Vitest, a real embedded Postgres, 248 tests), `npm run typecheck`, `npm run build`, `npm run build:site`.

- **Test mode** (`PAYMENT_PROVIDER=fake`, `ALLOW_SELF_DEAL=true`): one phone can be buyer and seller, and typing "paid" stands in for a transfer.
